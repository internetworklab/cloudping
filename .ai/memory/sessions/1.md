# Eliminate netlink dependency & 65535 as initial PMTU guess

## Task

1. Eliminate the dependency on the Linux netlink API (`github.com/vishvananda/netlink`), which occurs in the PMTU logic: netlink is used to determine the initial guess of PMTU.
2. After removal, use **65535** (maximum size of an IP/IPv6 packet, header included) as the initial guess of PMTU.
3. Reimplement `getSrcIP` in `pkg/tcping/tcping.go` another way (it also uses netlink).

## Investigation findings

netlink is used in exactly two places:

- `pkg/utils/mtu.go` — `GetNexthopMTU(destination, considerPMTUCache)` uses `netlink.NewHandle()` + `RouteGet` + `LinkByIndex` to get the nexthop interface MTU (optionally considering the kernel PMTU cache). Its only caller is `pkg/pinger/ping.go`, where the result feeds:
  - the initial PMTU guess (`*pmtu = nexthopMTU`, also reset to it when the last hop is found),
  - the `NexthopMTU` field of `pkgraw.ICMPSendRequest`,
  - `pkgraw.GetMaxPayloadLen(...)` as the MTU cap for payload truncation.
- `pkg/tcping/tcping.go` — `getSrcIP(dstIP)` uses netlink `RouteGet` to find the source IP for building TCP SYN headers.

Supporting facts:

- `GetMinimumMTU` (stdlib `net.Interfaces()`) is only used as fallback inside `GetNexthopMTU` → becomes dead code after removal.
- `GetMaximumMTU` (stdlib `net.Interfaces()`) is still used for raw-socket read buffers in `pkg/raw/icmp.go` and `pkg/tcping/tcping.go` → must be kept.
- `GetMaxPayloadLen(ipVersion, ipprotoNum, pmtu, nexthopMTU)` computes `min(pmtu, cap)`; the 4th arg is effectively an upper-bound cap, not necessarily a nexthop MTU.

## Considerations / design decisions

- **Initial guess = 65535**: add `MaxIPPacketLen = 65535` const in `pkg/utils/mtu.go` (documented as max IP/IPv6 packet length, header included; refined later by ICMP Fragmentation-Needed / Packet-Too-Big feedback). ping.go uses it instead of the netlink lookup.
- **Naming honesty**: `NexthopMTU` no longer means "nexthop MTU" once fed a constant 65535. Rename to `MTUCap` in `pkgraw.ICMPSendRequest` and `GetMaxPayloadLen` (param `mtuCap`). Rename is contained: types.go, common.go, icmp.go (4 sites), ping.go. Local var `nexthopMTU` → `initialMTUGuess`.
- **getSrcIP without netlink**: use the classic UDP-dial route-lookup trick — `net.DialUDP("udp4"|"udp6", nil, &net.UDPAddr{IP: dstIP, Port: 53})`; UDP `connect()` sends no packets, the kernel only does route lookup and binds the socket to the source address of the selected route; read it back via `LocalAddr()`. Works for both address families; handles "no route" via error/unspecified-IP check.
- **Error wrapping**: use `fmt.Errorf("...: %w", err)` per project conventions.
- After edits: `go mod tidy` to drop netlink (+ indirect netns) from go.mod/go.sum, then `go build ./...` and `go vet ./...` to verify.

## Outcome

Done. Summary of changes:

- `pkg/utils/mtu.go`: netlink-based `GetNexthopMTU` removed (along with its only helper, `GetMinimumMTU`/`standardMTU`); added `MaxIPPacketLen = 65535`; kept stdlib-only `GetMaximumMTU` (still used for raw-socket read buffers).
- `pkg/pinger/ping.go`: initial PMTU guess is now `pkgutils.MaxIPPacketLen` (65535), refined later by ICMP feedback; local var renamed `nexthopMTU` → `initialMTUGuess`.
- `pkg/raw/`: `ICMPSendRequest.NexthopMTU` → `MTUCap` (it is a payload-sizing cap, not a nexthop MTU); `GetMaxPayloadLen` param renamed `mtuCap`; 4 call sites in `icmp.go` updated.
- `pkg/tcping/tcping.go`: `getSrcIP` reimplemented with the UDP-dial route-lookup trick (`net.DialUDP` udp4/udp6 to the destination; no packets sent; kernel picks the source address). Works for both families and off-Linux.
- **Portability fix** (turned out to be the point of removing netlink): `pkg/raw/icmp.go` used Linux-only `syscall.IP_MTU_DISCOVER`/`IP_PMTUDISC_PROBE`/`IPV6_MTU_DISCOVER`/`IPV6_PMTUDISC_PROBE`, breaking the build on darwin. Extracted into `setSockOptPMTUProbe(fd, ipv6)` in new files `pkg/raw/pmtud_linux.go` (real implementation, behavior unchanged on Linux, incl. `IPV6_DONTFRAG=62`) and `pkg/raw/pmtud_other.go` (`//go:build !linux`, no-op). Call sites keep the panic-on-error semantics.
- `go.mod`/`go.sum`: `github.com/vishvananda/netlink` (and indirect `netns`) dropped via `go mod tidy`; no `vishvananda` references remain in the codebase.

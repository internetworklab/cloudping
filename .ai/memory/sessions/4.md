# Dedicated folder for integration test scripts

## Task

Move the last two integrated testing scripts — `scripts/run_integration_demo.sh` (hub + agent API suite, session 2) and `scripts/run_web_integration_test.sh` (embedded web assets + auth proxy suite, session 3) — into a dedicated folder, and record the change in a session note.

## Investigation findings

- The rest of `scripts/` is dev/launch helpers (example-cluster launchers, mmdb fetch, dockerized web proxy); the two `run_*` scripts are the only automated integration suites, so grouping them clarifies the folder.
- **Reference check (grep across repo)**: the old paths are mentioned only in session notes `2.md`/`3.md` (left untouched as historical record). No README/docs/CI references, no cross-references between the two scripts, and no `scripts/` self-references inside them.
- **Only breakage risk**: both scripts resolve the repo root as `PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"` — moving one level deeper would make it point at `scripts/`.

## Changes

- New home: `scripts/integration/run_integration_demo.sh`, `scripts/integration/run_web_integration_test.sh` (plain move; executable bit preserved).
- Both scripts: `PROJECT_ROOT` now `"$SCRIPT_DIR/../.."`. No other edits needed.

## Outcome

### Validation

Run from the new location with the existing binary (`SKIP_BUILD=1`):

- `scripts/integration/run_web_integration_test.sh` (+ `SKIP_WEB_BUILD=1`) → **25 passed, 0 failed** (static/auth/proxy modes all green).
- `scripts/integration/run_integration_demo.sh` → **4 passed, 4 skipped** — skips are the raw-socket tests (ICMP/TCP/ICMPv6 ping); `bin/globalping` lost its setuid-root bit in the session-3 rebuild. Re-apply with `sudo chown root:wheel bin/globalping && sudo chmod u+s bin/globalping` to get the full 8/8.

## Follow-ups

- Session notes `2.md`/`3.md` still cite the old `scripts/run_*.sh` paths — intentional (historical record); the canonical location is now `scripts/integration/`.
- If `run_web_integration_test.sh` gets wired into CI (open item from session 3), use the new path.
